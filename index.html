DPDP-Compliance-Engine-Simulator

GitHub ↗
Independent proof-of-concept
DPDP ActFastAPIData Protection
Problem

A data-erasure request under Section 6(4) of the DPDP Act, 2023 can directly conflict with statutory retention mandates under the PMLA, CGST Act, and Companies Act — with no clear resolution logic.

Output

A FastAPI service modelling that cross-statute conflict as an explicit decision tree (10 passing tests), deciding whether a record should be hard-deleted, declined, or preserved with targeted pseudonymization.

Next

Statutory citations are currently flagged in-repo as undergoing primary-source verification — treated deliberately as a PoC, not a compliance product, until that verification is complete.

Thought process
Erasure request under DPDP §6(4)→ Cross-check PMLA / CGST / Companies Act→ Decision tree logic→ Hard-delete / Decline / Pseudonymize

ArgLex — Argument-Level Legal Retrieval System

GitHub ↗
2025–2026
Retrieval-OnlyLegal AISSRN Publication
Problem

Case-law databases return full-case dumps; an advocate mid-brief needs the specific argument, not the whole decision.

Output

A publicly deployed retrieval tool built on 99 manually curated arguments across 16 Supreme Court decisions, using a multi-layer pipeline combining semantic search with a legal-domain model trained on 5.4M Indian legal documents. Deliberately retrieval-only — no generative output — to preserve advocate judgment and remove hallucination risk.

Next

Expanding corpus coverage and refining retrieval precision against advocate feedback.

Publication

"Beyond the Hallucination: Building a 'Retrieval-Only' Future for Indian Legal Tech" — SSRN, Apr 2026.

Thought process
Gap: full-case dumps vs. argument-level need→ 99 arguments curated, 16 SC decisions→ Semantic search + domain model (5.4M docs)→ Retrieval-only output, no generation
